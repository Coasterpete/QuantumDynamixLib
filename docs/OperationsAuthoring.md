# Operational track segments and devices

Open **Track Workspace → Operations…** to see the track segment list in the existing left panel. The Operations command toggles back to the geometric Region List. Select a segment in the list or click its heartline overlay in the viewport. **Add Track Segment…** starts with the first unassigned interval. **Track Segment Settings…** edits the selected segment.

**Normal Track** has no attached device. **Transport** attaches one **Idealized Powered Transport** device. The entry speed is an independent input in m/s. New devices start with a copy of the track's reconstruction speed, which is editable here. Leave the optional speed limit blank for unrestricted motion.

## Station policy

Track segment endpoints are absolute heartline stations in metres. Segments may cross any number of geometric, force-based, or coordinate-acceleration Regions. Two operational segments may share an endpoint. Gaps in the operational segment list are allowed. Editing, moving, renaming, or resizing a geometric Region preserves the segment endpoints at their authored stations, so an endpoint can move to a different world position as the heartline changes. A geometry edit that would leave an endpoint outside the heartline is rejected. Change or remove the affected segment first. The viewport draws the overlay along the existing heartline with exact evaluated endpoints.

Each device Acceleration Region uses offsets in metres measured from its segment start. Moving a segment carries these offsets with it. Changing a segment's length preserves the offsets. If an interval falls outside the new length, edit its offsets before applying settings. Acceleration Regions can have gaps and shared endpoints. They are independent of geometric Region boundaries and stay within the device's segment. Gaps command zero acceleration. At a shared endpoint, motion readouts use the outgoing command. At the end of the entire segment, they use the final inward limit.

## Edit and calculate

1. Choose **Transport** in Track Segment Settings and enter the entry speed and optional limit.
2. In the embedded **Acceleration Region Editor**, add an interval or select one. The graph shows every Acceleration Region of the device on one offset axis from 0 to the segment length. Click a curve to select its Acceleration Region and Transition. Drag an interior keyframe to change its offset and command. Drag a first or last keyframe to change only its command. Drag an Acceleration Region boundary to change its offset. A boundary shared by two Acceleration Regions moves both. A free boundary stays within its gap. The curves preview each valid position. An invalid position keeps the last valid preview. For exact values, set the start and end offsets and choose **Apply Offsets**. Resizing preserves the relative position of each interior keyframe within that interval. Graph edits change only the settings draft. Scroll or drag empty graph space to zoom and pan, or use **−**, **+**, and **Fit**.
3. Select a Transition. **Split** inserts a key at its midpoint using the evaluated command. The first resulting span retains the original easing and the second starts Linear. **Merge** removes a shared key and makes the resulting span Linear. Choosing an **Easing** or **Direction** applies it at once and updates the graph and its label. A rejected choice returns the selector to the applied easing. Type a length or endpoint accelerations, then press Enter or choose **Apply Transition**. Equal start and end accelerations draw a flat line for every easing, and the editor notes this. **Undo** and **Redo** in the editor header, or Ctrl+Z and Ctrl+Y (Cmd on macOS), step through this window's draft edits. Adjacent spans of one Acceleration Region share their endpoint values. When editing the last span's length, its end stays fixed and its start moves. For a single span, change the enclosing offset range to change its length.
4. Choose **Calculate Longitudinal Motion**. The summary shows the end or stop station, speed, and elapsed time. Enter an offset and choose **Read Sample** to see station, speed, elapsed time, commanded acceleration, and calculated acceleration. **Apply Settings** commits the draft as one Undo/Redo action. The main editor's Undo/Redo and saved-state tracking include both operations and geometry edits. Reopening starts a fresh history.

## Prescribed longitudinal motion

The authored curve is forward coordinate acceleration in m/s² along increasing heartline station. Positive accelerates and negative decelerates. The existing distance trajectory integrates \(v^2(s)=v_0^2+2\int a(s)\,ds\) and elapsed time \(\int ds/v(s)\) while forward speed stays positive. Each supported easing is monotone within its authored span. A change of acceleration sign splits calculation at the zero crossing so the speed-limit search works on a monotone speed interval. At the speed limit, positive commands are suppressed and the model coasts at the limit. A negative command resumes deceleration. The command curve remains available for comparison with the calculated acceleration. Numeric integration failures include the affected offsets and diagnostic where available.

The existing time trajectory handles constant-command spans, including departure from rest under positive acceleration and braking to an exact zero-speed endpoint. A stop ends the forward result at that offset. Its readout shows zero speed and zero calculated acceleration after stopping. Sampling beyond a stop is unavailable. Zero or negative command at rest leaves the model stationary. A nonlinear distance Transition requires positive forward speed throughout. A nonlinear launch from rest or nonlinear stop produces a diagnostic. Use a constant positive launch span or a constant braking span for these cases. The calculation can be repeated after correcting the inputs.

This is a prescribed-motion prototype for one selected device interval, with no inter-segment speed handoff. It does not model physical assemblies, articulated train motion, motor torque, traction, gravity, drag, or rolling resistance. Operational speed never enters Force-based or Geometric Region reconstruction. Device definitions, scalar commands, and calculated trajectories are separate. Future physical devices can use the segment boundaries and their own configuration and state without extending the geometry-authored Region list.
